| **A.** A fonte do bug do usuário: bebidas têm `SUBGROUPS["bebidas"]`, então MenuView ignora `productGroups` e mostra as caixas hardcoded — qualquer grupo "Refri 350ml" criado no Admin nunca aparece no PALM como popup. E o card "Porco" é renderizado separado, num fluxo paralelo, não-arrastável.Solução: unificar em `product-groups` + tornar grupo um "card pseudo-produto" arrastável**1. Eliminar** `SUBGROUPS` **hardcoded e seed automático em** `product-groups`- Apagar `SUBGROUPS`, `matchesSubgroup`, `Subgroup`, `PORCO_VARIANTS`, `HIDDEN_ESPETO_NAMES` de `menu-subgroups.ts` (arquivo fica vazio — deletado).- Apagar `SubgroupDialog.tsx` (substituído por `GroupVariantDialog`).- Migração SQL de **seed**: ler `settings.product_groups` atual; se faltarem grupos equivalentes aos antigos `SUBGROUPS` (Refri 350ml, Mini 220ml, Refri 600ml, Refri 1L, Refri 2L, KS 290ml, Sucos Del Valle 290ml, Água), criar com: - `category: "bebidas"`, `icon` apropriado (🥤/🧃/💧), `member_names` = lista atual de matchers convertida para nomes reais de produtos. - `trigger_product_name` = primeiro membro existente (ex: "Coca-Cola 350ml" para "Refri 350ml").- O grupo "porco" continua existindo como qualquer outro — sem hardcode em código.**2. PALM: card de grupo entra na grade como item ordenável**`MenuView.tsx`:- Remove imports de `SUBGROUPS/matchesSubgroup/Subgroup/SubgroupDialog`.- Remove ramo `subgroups ? ... : ...` na renderização — sempre roda o ramo dinâmico.- Tipo de item da grade vira união: ```ts type GridItem = | { kind: "product"; id: string; product: Product } | { kind: "group"; id: string; group: ProductGroup; trigger: Product; variantCount: number }; ```- `gridItems` é construído assim: - Começa com produtos filtrados (excluindo membros de grupos). - Para cada `activeGroup`, **substitui** o card do `triggerProduct` por um item `{ kind: "group" }` (mantendo o `id` do produto trigger, então a ordenação manual já existente ainda funciona). - Aplica `sortByPersistedOrder(gridItems, orderMap[activeCategory])` — como o id do grupo é o id do produto trigger, ele participa da mesma ordenação.- Renderização: switch por `kind` — produto vira card simples, grupo vira card com selo `{icon} GRUPO` que abre `GroupVariantDialog`.- Resultado: grupos aparecem misturados com produtos, na ordem definida no Admin, idêntico em comportamento.**3. Admin: grupo aparece como "card especial" arrastável na grade**`ProductsManager.tsx` + `SortableProductCard.tsx`:- Mesma transformação: a grade do admin vira lista de `GridItem`. Substitui o card do produto-trigger por um card de grupo.- Novo componente `SortableGroupCard.tsx` (espelha `SortableProductCard`): - Mesmo handle de drag (`useSortable` com `id = trigger.id`), mesmo z-index/transform. - Mostra ícone, nome do grupo, "{N} variantes", botão "Editar grupo" (abre `GroupsManager` já no item editado). - Botão "Visível/Oculto" toca em `triggerProduct.active` (igual produto normal).- Como o `id` é o do produto-trigger, **a mesma** `product_order_<categoria>` ordena tudo: grupos e produtos misturados.- Os banners `ProductGroupBanner` continuam acima da grade como referência (informa quais produtos estão "dentro do popup"), mas o card-trigger substituído já mostra o conteúdo principal.**4.** `porco-group.ts` **reduz ao mínimo**- `ItemFormDialog` deixa de importar `PORCO_GROUP_NAMES`/`PORCO_EXTRA_NAMES_KEY`. Em vez disso, usa `useProductGroups()` para detectar se o nome do item de estoque pertence a algum grupo (qualquer grupo, não só Porco) e aplicar a mesma UX de "este item participa do grupo X".- `porco-group.ts` é **deletado** depois de migrar `ItemFormDialog`.**5. Banner de grupo: visualização universal no Admin e Estoque**`ProductsManager.tsx` e `Stock.tsx` já iteram `getGroupsForCategory(productGroups, activeCategory)` e renderizam `ProductGroupBanner`. Isso continua igual. O único ajuste: como o card-trigger agora vira "card de grupo", o banner fica mais informativo ("estes são os membros do popup").Comportamento final (por requisito do usuário)- ✅ "Todo item pode ser produto OU grupo" → grupo é representado pelo produto-trigger, com tipo `kind: "group"` no rendering. Mesma persistência de ordem, mesmo CRUD.- ✅ "Grupos movíveis (drag & drop)" → `SortableGroupCard` participa do mesmo `DndContext` que produtos.- ✅ "Não existir grupo hardcoded" → `SUBGROUPS`, `PORCO_VARIANTS`, `HIDDEN_ESPETO_NAMES`, `porco-group.ts` deletados. Fonte única: `settings.product_groups`.- ✅ "No Admin grupos aparecem na mesma lista dos produtos" → grade unificada de `GridItem`.- ✅ "No PDV PALM: produto adiciona direto, grupo abre popup" → switch por `kind`.- ✅ "Porco se comporta como qualquer grupo + bebidas viram grupos reais no PDV" → seed migra Refri/Mini/etc. para `settings.product_groups` e elimina caminho paralelo.Arquivos**Editados**- `src/components/palm/MenuView.tsx` — remove SUBGROUPS, unifica grade com `GridItem`, remove SubgroupDialog.- `src/components/admin/ProductsManager.tsx` — grade unificada com GridItem; passa grupos para o DndContext.- `src/components/admin/SortableProductCard.tsx` — sem mudança (continua para produtos puros).- `src/components/stock/ItemFormDialog.tsx` — deixa de importar de `porco-group.ts`; usa `useProductGroups`.- `src/components/palm/menu-subgroups.ts` — **deletado**.- `src/components/palm/SubgroupDialog.tsx` — **deletado**.- `src/lib/porco-group.ts` — **deletado** após migrar `ItemFormDialog`.**Novos**- `src/components/admin/SortableGroupCard.tsx` — card arrastável para grupo no Admin.**Migração SQL**- Seed `settings.product_groups` com os grupos de bebidas equivalentes aos `SUBGROUPS` hardcoded (idempotente — só adiciona os que faltam, mantendo os existentes).O que NÃO muda- Schema: nenhuma alteração em `products`, `inventory_items`, `orders`.- API/RPCs.- Lógica de carrinho, impressão, estoque, ESGOTADO.- A 4 categorias permanecem.- Ordens persistidas (`product_order_<categoria>`) continuam válidas — grupos usam o id do produto-trigger.Antes de implementar — uma confirmaçãoA migração SQL vai **criar automaticamente** os seguintes grupos em bebidas, baseados nos subgrupos hardcoded atuais:- 🥤 Refri 350ml, Refri 600ml, Refri 1L, Refri 2L- 🧊 KS 290ml- 🥃 Mini 220ml- 🧃 Sucos Del Valle 290ml- 💧 ÁguaCada grupo terá como **trigger** o **primeiro membro existente** (ex: "Coca-Cola 350ml" vira o card de "Refri 350ml" no PALM, com selo 🥤 GRUPO).
